# AI 功能的行为规格

仅在功能实际使用 AI、检索、推荐或自动决策时加载。传统 CRUD 功能无需增加空的模型章节。

## 行为契约

| 项目 | 必须明确的内容 |
|---|---|
| 用户任务 | AI 帮用户完成什么，最终责任与可编辑部分 |
| 输入 | 用户输入、上下文、检索资料、权限和来源 |
| 策略 | 必须遵循的业务规则；可由模型判断的部分 |
| 输出 | 格式、证据/引用、置信表达、失败状态 |
| 交互 | 需要澄清、拒答、转人工或允许用户修改的条件 |
| 工具动作 | 可用动作、参数约束、当前授权和执行回执 |
| 异常 | 无资料、低质量输入、工具超时、模型不可用等处理 |

关键业务事实、资格、金额、权限和状态转换应由确定的规则或权威系统提供；模型不能因“认为合理”而改写。引用应可定位到实际输入来源，不能仅看起来像引用。

策略规格可使用“输入信号 → 决策条件 → 输出/动作 → 兜底”表。不同策略之间说明优先顺序和冲突处理，避免多个“最高优先级”。模型名称和参数以现有架构为准；选择尚未完成时给比较标准，不编造选型结果。

## 冷启动与降级

新用户、空知识库、无历史行为分别如何工作；是否使用预设内容，预设内容如何标记。无检索依据时可返回信息不足、请求补充或降级到已授权的基础功能；不得生成假证据填满结果。

对长任务说明进度、取消、重试和重复动作的处理。高影响的外部动作要遵循业务及宿主既有授权；不默认因为使用 Agent 就每步追问，也不把一次授权扩大到其他动作。

## 评测与上线证据

每个核心行为关联测试任务和评分规则，例如字段提取准确性、引用支撑、工具参数正确性、拒绝条件是否符合规则、用户是否完成任务。根据功能区分检索质量、生成质量、工具执行和最终业务结果。

记录样例来源、覆盖的失败类、留出集、人工标注方法、可复现运行配置。评测规模由错误后果、场景覆盖和预算决定，不指定通用“50 条足够”或“85% 即可上线”。

发布条件包含已确认的质量、成本、时延、护栏和回退触发。A/B 假设与主要指标可在 PRD 中定义；统计结论需要真实实验数据和适当方法，不能用离线样例成绩替代线上业务效果。

若记录模型输入输出，另说明哪些内容会离开进程、存储范围、保留时间、访问者和删除方式；不要默认将整段用户资料纳入日志或评测集。
