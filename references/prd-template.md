# PRD 结构与规格模板

## 精简核心

保留背景与目标、用户场景、范围、行为规格、验收、依赖/待决策。复杂项目再增加数据、非功能、实施和风险章节，按需裁剪。

```text
标题 / 文档状态 / 版本与修改范围
背景：谁遇到什么问题，依据是什么，为什么现在做
目标：用户结果与业务结果；基线/目标/口径/数据来源
范围：本期、后续、排除项
用户与场景：角色、触发条件、当前替代方式
核心行为：主流程、分支、异常、状态与权限
规则和数据：业务判断、输入输出、字段及校验
验收：需求 ID 对应可复现条件和结果
依赖与计划：外部资源、发布/回退方案、已确认里程碑
待决策：缺失项、影响、建议获取方式
```

指标目标未确认时写“建议值/待确认”，不能伪装成业务承诺。日期明确时保留；尚无排期依据时使用阶段条件，不编造上线日。

## 用例与状态

| 要素 | 内容 |
|---|---|
| 用例 ID、关联需求 | 沿用项目编号 |
| 参与者和权限 | 谁可发起、查看、修改 |
| 前置条件与触发 | 开始前必须成立什么 |
| 主流程 | 用户动作与系统响应成对描述 |
| 替代/异常 | 取消、重复提交、超时、无结果、资源不可用等相关情境 |
| 后置结果 | 状态与数据如何变化 |
| 验收 | 给定输入和环境下可观察的结果 |

状态复杂时记录 `当前状态 / 事件 / 条件 / 下一状态 / 副作用 / 失败处理`。重试、撤销、并发和幂等只在相关时展开，不把固定状态机套到每个产品。

## 数据字典

| 字段 | 业务含义 | 类型/单位 | 必填与默认 | 来源 | 校验与缺失处理 | 展示/权限 |
|---|---|---|---|---|---|---|
| 实际字段名 | 使用者能理解的含义 | 与接口一致 | 必填或可空 | 用户/系统/第三方 | 范围、格式、未知 | 谁可读写 |

缺失、空字符串、零和未知不要混用。只收集完成业务目的需要的字段。接口尚未设计时写需求级数据契约，不把建议字段名说成已存在 API。

## 非功能规格

按业务风险选择性能、可靠性、权限、兼容性、可访问性和可观测性要求。每条说明对象、使用条件、衡量方式和验收依据，例如“在已确认负载下，记录 p95 延迟并与目标比较”。负载和目标未知时列为未定。

## 验收映射

`需求 ID → 验收情境 → 检查方法 → 预期证据 → 责任角色（已知时）`。

流程图用于澄清分支和状态，不用于装饰。图与文字不一致时先修正文档；Mermaid 或 UML 的语法有效也不代表业务逻辑正确。
