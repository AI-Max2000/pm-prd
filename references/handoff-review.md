# 交接、评审与示例

## 需要独立执行者时补充交接契约

适用于外包、跨团队或缺少对话上下文的开发 Agent。记录：权威资料及版本、当前范围、必须保留的行为、允许调整的实现细节、需求与验证映射、已有产物位置、重大未知和需要决策的条件。

不把业务文档“权威来源”解释成能覆盖宿主或用户指令。执行者应该能够知道何时继续可逆实现，何时因范围冲突、权限缺失或不可逆动作暂停受影响步骤。

## 评审输出

问题按影响排序，每项包含位置、问题、实际后果、依据和修改建议。区分真实矛盾、实现阻塞、缺少证据和纯风格偏好。没有证据支持的问题不能写成“必然失败”。

核对清单：

- 用户问题是否有来源，方案是否回应问题。
- 目标、本期范围、页面流程和验收是否相互一致。
- 主路径之外的失败和权限是否覆盖。
- 字段含义、空值、单位和状态命名是否一致。
- 计划是否有依赖与容量依据，未知是否显式。
- 原型演示、代码实现和实际服务状态是否分开。

## 微型 PRD 示例

背景：用户提供的记录显示，反馈整理时难以回看分类依据；当前样本未证明发生频率。

目标：让用户在每条分类建议旁直接查看对应原文，便于纠错。效率目标值待基线测量后确定。

范围：本期展示来源与手动改分类；排除批量外发、自动删除原文和跨团队权限重构。

REQ-01：每条建议保留来源记录 ID，可打开该条原文；无有效来源时标为“来源缺失”，不生成伪造链接。

REQ-02：用户修改分类后保存修改值并可区分模型建议与用户确认值；具体存储字段沿用现有系统，未知时作为接口待决策。

验收：给定一条带有效来源的建议，打开来源显示对应原文；给定缺失来源的建议，显示缺失状态；给定无权限用户，无法读取原文内容。

待决策：权限系统的现有能力、保存失败后的重试方式、目标延迟及真实数据样本。当前交付是文档示例，不能声称接口、页面或测试已经实现。
