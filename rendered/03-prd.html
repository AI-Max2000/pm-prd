PRD 规格：人工确认与导出的行为契约

统一场景：回声，一款面向小型产品团队的反馈整理工具。
合成场景 · PRD 成稿

回声：人工确认与导出 PRD

文档状态：演示需求稿。输入为本次设定的 8 条合成反馈，本文定义目标行为，不代表生产实现；本次另附聚焦审核与导出的本地原型。

要解决的问题

产品经理需要把整理结果交给研发，但 AI 建议可能误判，模糊反馈也不能直接成为需求。本期保证“每条可回查、人工能修改、确认后才导出”。暂不接入渠道、不自动排优先级或创建研发任务。

主流程与规则

  1. 读取带 ID 的反馈，展示原文、建议主分类、简短依据和“待确认”状态。F001、F003 均建议 bug，关联为同一问题，但保留两条原记录。
  2. 用户查看原文，可保留建议或改分类，再点击“确认”。F007 信息不足、F008 含非反馈指令，均置为 needs_review；该分类下确认按钮不可用，展示“请根据原文选择分类；信息不足可继续保留”。不得执行 F008 的发名单指令。
  3. 确认成功后计数立即更新。若之后修改分类或问题关联，自动撤销该条确认，提示“内容已变更，请重新确认”。原始建议不覆盖，便于追溯修改。
  4. “导出已确认项”显示当前可导出的条数。数量为 0 时不可触发；有记录时生成 CSV，包含 ID、原文、初始建议、最终分类、确认状态、原建议依据和关联反馈 ID。导出不会自动确认其他记录，也不会删除已导出项。

需求级字段与状态

以下字段为实现建议，尚无真实接口。

字段 规则
id、original_text 必填；ID 在批次内唯一；原文只读
suggested_category 六类枚举之一；保留初始建议
reviewed_category 初始为空；人工选定后写入；有效分类取人工值，否则取建议值
review_status 初始 unconfirmed；仅有效分类非 needs_review 时可变为 confirmed
related_ids 数组，可为空；只引用同批 ID，关联不影响原记录数量

确认状态由程序规则维护，模型不得写入。生成 CSV 时冻结当前确认记录的版本快照；生成期间发生修改，导出结果仍对应提示中的快照，不混入新版本。

异常与验收

ID 给定操作 可观察结果
R01 首次载入 8 条输入 8 条均未确认；导出数为 0；F007、F008 不能直接确认
R02 确认 F001、F003 后导出 CSV 恰有 2 条，均能回查各自原文；重复关联不吞记录
R03 已确认 F001 后改分类 F001 回到未确认；再次导出只含仍确认的 F003
R04 同一确认动作重复触发 只确认一次，计数不重复增加
R05 输入 ID 冲突或生成文件失败 冲突记录不覆盖旧原文；失败保留确认状态并允许重试

CSV 需正确转义逗号、双引号及换行，防止反馈文本被表格软件当作公式执行。初期只承诺本地文件生成可验证；下载触发不能证明用户已打开文件。浏览器兼容范围、保存期限与真实模型接入方案仍待立项确认。

原建议依据始终解释 suggested_category，不代表人工修改后的理由；CSV 使用 suggestion_reason 字段明确归属。本期不增加人工备注功能。
